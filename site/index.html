Clave protege cada conversación desde el navegador. El servidor entrega sobres cifrados, pero nunca recibe el contenido legible ni las claves privadas.

Arquitectura

El servidor transporta; los clientes protegen.

Cliente

Criptografía local

Genera identidades, cifra mensajes, verifica firmas y conserva las claves privadas cifradas en el dispositivo.

API

Autenticación y entrega

Gestiona cuentas, sesiones y conexiones WebSocket sin procesar el texto de las conversaciones.

Persistencia

Cola cifrada

SQLite conserva claves públicas, sobres cifrados, estados de entrega y auditoría sin contenido sensible.

Controles principales

Protección en cada etapa del mensaje.

X25519 + HKDF
Acuerdo y derivación de una clave contextualizada para cada mensaje.
AES-256-GCM
Confidencialidad e integridad autenticada del contenido.
Ed25519
Firma del sobre para autenticar remitente y campos críticos.
Huella SHA-256
Verificación de claves por un canal independiente y bloqueo ante cambios.
Argon2id
Almacenamiento resistente de contraseñas en el backend.
TLS 1.3
Protección adicional para credenciales, sesiones y metadatos en tránsito.

Alcance honesto

Un prototipo académico, no un protocolo de producción.

Clave demuestra un flujo completo y verificable de mensajería cifrada. No ofrece anonimato de metadatos, recuperación de claves perdidas, múltiples dispositivos ni Double Ratchet. Estas limitaciones están identificadas para no atribuir al sistema garantías que todavía no implementa.
